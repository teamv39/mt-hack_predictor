## 2. Суть задачи и продуктовая концепция

### Боль города (Дептранс / Мосгортранс / ЦОДД)
Сейчас диспетчеры видят проблему постфактум, когда автобус уже застрял, а интервал сорван. Главный кошмар пассажиров — **«пачкование» (Bus Bunching)**, когда 20 минут нет ни одного рейса, а потом приезжают три автобуса подряд.

### Наше решение
Мы создаем **не просто прогноз задержек, а Проактивную систему поддержки принятия решений (DSS)**:
1. **Прогноз за 15–40 минут:** ML-модель заранее обнаруживает риск срыва графика и схлопывания интервалов.
2. **Объяснимый ИИ (XAI):** Модель показывает диспетчеру причину задержки (пробка на перегоне, затянувшаяся посадка из-за дождя, светофор).
3. **Готовое действие (Actionable UI):** Система не просто кричит об ошибке, а предлагает готовую кнопку: *«Придержать следующий борт на 2.5 мин на остановке Х, чтобы интервал не схлопнулся»*.

## 3. Итоговое распределение ролей в команде (4 человека)

Вы вчетвером закрываете полный цикл: от сырых логов до реактивного бэкенда, точного ML и сочного фронта.

```
┌────────────────────────────────────────────────────────┐
│                   ДЕНИС (Team Lead)                    │
│      Продукт • Логика решений • Golang Backend • Питч  │
└───────┬───────────────────┬────────────────────┬───────┘
        │                   │                    │
        ▼                   ▼                    ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│    АРТЕМ     │────►│     МИША     │────►│   КИРИЛЛ     │
│   Data Eng   │     │   Lead ML    │     │   Frontend   │
│ Данные, гео, │     │   Модели,    │     │ Дашборд ЦОДД,│
│  ETL, фичи   │     │ SHAP, метрики│     │ карта, UI/UX │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 1. Денис — Team Lead / Product / Go Backend
* **Управление и Продукт:**
  * Контроль дедлайнов, защита скоупа задач, согласование API-контрактов.
  * Формулировка бизнес-логики регулирования (правила для *Holding* и выравнивания *Headway*).
  * Подготовка финального питч-дека (презентации) и защита перед жюри.
* **Golang Backend:**
  * **Главный козырь перед жюри:** бэкенд на Go — идеален для телеметрии (держит тысячи запросов в секунду от реального парка с микросекундным latency).
  * Написание REST API на Go (Gin / Chi / Fiber) для отдачи данных на фронт (`/routes`, `/vehicles`, `/alerts`).
  * Эмулятор потока данных (Data Feeder на Go): считывает файлы логов по таймеру и «проигрывает» их во времени, имитируя живой эфир телеметрии.
  * Интеграция с ML (вызов локального Python-сервиса через REST/gRPC или инференс через Go ONNX Runtime).
  * Упаковка всего бэкенда в Docker.

### 2. Миша — Lead ML / Data Scientist
* Обучение регрессионной модели времени хода и задержки ($\Delta t$) на базе **CatBoost / LightGBM**.
* Обучение модели классификации рисков пачкования (вероятность инцидента 0–100%).
* Строгая хронологическая валидация (`TimeSeriesSplit`) для исключения Data Leakage (заглядывания в будущее).
* Формирование весов важности признаков (SHAP) для объяснения причин опоздания в UI.
* Обертка инференса в легковесный Python/FastAPI сервис или экспорт в ONNX для Go-бэкенда Дениса.

### 3. Артем — Data Engineer
* Первичная очистка «грязных» GPS-треков (фильтрация скачков координат, стоянок в парке).
* **Map-Matching:** алгоритм геометрической проекции координат бортов на граф остановок и маршрутов.
* **Генерация ключевых фичей:**
  * Расчет **Headway** (дельта времени до впереди и позади идущего борта).
  * Кумулятивное отставание борта по предыдущим остановкам рейса.
  * Скользящие средние скоростей по участкам сети за последние 15/30/60 минут.
* Сборка итогового чистого обучающего датасета для Миши и пайплайна предобработки для продакшна.

### 4. Кирилл — Frontend Developer / UI
* Разработка дашборда **«Ситуационный центр Московского транспорта»** (React + Tailwind CSS).
* Интерактивная карта (Mapbox GL JS / Leaflet) на весь экран в тёмном стиле.
* Отрисовка линий маршрутов (зеленый/желтый/красный статус) и движущихся маркеров автобусов с бейджами задержек.
* Левая панель: «Предиктивный радар» (лента карточек алертов с таймерами «через ХХ мин»).
* Правая панель: Инспектор выбранного борта:
  * Продольный график: *«План vs Прогноз без мер vs С рекомендацией ИИ»*.
  * SHAP-разбор факторов опоздания (пробка, посадка, погода).
  * Кнопка прямого действия: **[✓ Применить и передать в АСУ]**.

## 5. UI/UX Спецификация для Кирилла (Фронтенд)

* **Стиль:** Монолитный **Dark Mode** (`#0B0F17` / `#0F172A`).
* **Компоновка:** Карта развернута на **100% экрана**, а информационные панели сделаны **парящими стеклянными карточками поверх карты** (`backdrop-blur-md bg-slate-900/80 border border-slate-800/80 rounded-2xl`).

### Главные экраны и элементы:
1. **Top Bar:** 
   * Логотип «Московский транспорт | Предиктор 2.0».
   * Индикатор: `● LIVE SIMULATION (Go Core: 4.2ms)`.
   * Метрики: «Пунктуальность: 94.8%», «Активных алертов: 3», «Предотвращено сбоев: 19».
   * Кнопки таймлайна: `Play / Pause`, скорость `x1 / x5`.
2. **Левая парящая панель (Radar):**
   * Карточки алертов с обратным отсчетом: `ЧЕРЕЗ 22 МИН | м3 | РИСК ПАЧКОВАНИЯ (89%)`.
   * Клик по карточке плавно приближает карту (`flyTo`) к проблемному перегону.
3. **Карта (Center):**
   * Маркеры автобусов со стрелками направления и плашками опоздания (`№1042 | +12m`).
   * Пульсирующая красная линия между двумя сближающимися автобусами — зона риска пачкования.
4. **Правая панель (Инспектор инцидента):**
   * **График траектории:** 
     * 🔵 Синяя линия: План.
     * 🔴 Красная линия: Прогноз без регулирования (уходит в сильный срыв графика).
     * 🟢 Зеленая линия: Прогноз с применением рекомендации ИИ (выравнивается в график!).
   * **Факторы задержки (SHAP):** Горизонтальные бары (Пробка на Бауманской: 65%, Посадка из-за осадков: 25%, Светофор: 10%).
   * **Кнопка решения (CTA):** Сочная изумрудная кнопка `[✓ Применить рекомендацию: Придержать борт №1043 на 2.5 мин]`. При клике красная линия на графике превращается в зеленую!
