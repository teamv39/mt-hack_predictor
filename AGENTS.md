# 🤖 Инструкция для AI-агентов (AGENTS.md)

> **Проект:** Интеллектуальный ситуационный предиктор сбоев и интервалов движения общественного транспорта  
> **Контекст:** MT-Hackathon (Хакатон Московского Транспорта), Трек №3  
> **Тимлид:** Денис (@shteppinson)

---

## 1. Контекст и продуктовая суть

Разрабатывается **проактивная Система Поддержки Принятия Решений (СППР / DSS)** для диспетчеров наземного городского транспорта.

* **Ключевая проблема:** «Пачкование» автобусов (*Bus Bunching*) и схлопывание интервалов (*Headway collapse*).
* **Решение:**
  1. **Предикт за 15–40 минут:** ML заранее выявляет риски нарушения интервалов и задержек.
  2. **Объяснимый ИИ (XAI):** Факторный анализ на базе SHAP показывает первопричины сбоев.
  3. **Готовое действие (Actionable UI):** Рекомендации диспетчеру (стратегия *Holding* — регулировочная задержка, перераспределение выпусков).

## 2. Архитектура и стек технологий

```
mt-hack_predictor/
├── backend/    # Go (Chi, WebSocket, Data Feeder, NDTP TCP :9201, REST :8080)
├── frontend/   # React 19 + TypeScript + Vite + Tailwind CSS v4 + Leaflet (:5173)
├── ml/         # Python 3.12, uv, CatBoost, FastAPI (:8000), SHAP
├── data/       # Датасеты и веса моделей (не коммитятся в git)
└── docs/       # Архитектурная документация и API-контракты
```

* **Backend (`backend/`):** Высокопроизводительный Go-сервер. Обработка телеметрии в реальном времени, WebSocket-рассылка на UI, расчет метрик интервалов, TCP-приемник NDTP.
* **Frontend (`frontend/`):** Интерактивный дашборд диспетчера. Карта маршрутов и бортов, радар алертов, инспектор рейсов, графики план/факт/рекомендация.
* **ML (`ml/`):** Пайплайн обучения и инференс-сервис. Модели предсказания задержек и вероятности сбоев, расчет SHAP-факторов.
* **Docs (`docs/`):** Единый источник правды для межсервисного взаимодействия.

## 3. Инженерные правила и стандарты

### 3.1. Контракты данных — единый источник правды
* Все схемы взаимодействия между бэкендом, ML и фронтендом зафиксированы в `docs/api_contracts.md`.
* Если меняется структура данных или эндпоинт:
  1. Обновить `docs/api_contracts.md`.
  2. Синхронизировать типы: `backend/internal/models/types.go`, Pydantic-схемы в `ml/` и интерфейсы/типы в `frontend/src/`.

### 3.2. Качество и модульность кода
* **Без спагетти:** Держи файлы компактными (ориентир 200–400 строк). Разделяй логику по слоям (SRP).
* **Строгая типизация:**
  * Python: строгие схемы Pydantic v2 с валидацией, аннотации типов.
  * Go: явные структуры с json-тегами.
  * TypeScript: строгие интерфейсы без `any`.
* **ML-специфика:** Валидация строго через `TimeSeriesSplit` (не допускать утечки данных из будущего).
* **Frontend UI/UX:**
  * Соблюдать аккуратную сетку, отступы (padding/margin), консистентную типографику и цветовые маркеры статусов (зелёный/оранжевый/красный).
  * Учитывать особенности Tailwind CSS v4 (`@import "tailwindcss";`, без лишних устаревших конфигов).

### 3.3. Документация без фанатизма
* Читай документацию **точечно** — только те файлы из `docs/`, которые непосредственно относятся к текущей задаче. Не вычитывай всю папку `docs/` на простые вопросы или мелкие правки.
* Если выполнена крупная функциональная задача — отметь статус в `docs/implementation_plan.md`.

## 4. Рабочий процесс и Git Flow

1. **Ветки:**
   * Основная рабочая ветка — `dev`. Прямые коммиты в `main` запрещены (только релизы).
   * Новые фичи и фиксы делаются в тематических ветках: `feat/<name>`, `fix/<name>`, `refactor/<name>`, `docs/<name>`.
2. **Синхронизация:**
   * Перед началом крупной работы убедись, что ветка актуальна: `git pull origin dev`.
3. **Проверка перед коммитом:**
   * Код обязан собираться без ошибок: запускай `make check` или сборку соответствующего подпроекта.
4. **Коммиты:**
   * Осмысленные сообщения в формате Conventional Commits (`feat(scope): ...`, `fix(scope): ...`).
5. **Запрещено:**
   * Коммитить файлы весом > 10 МБ, дампы данных, архивы, кэши, бинарники и модели.
   * Использовать `git push --force` в общие ветки.

## 5. Шпаргалка команд

| Действие | Команда |
|---|---|
| Полная проверка сборки и тестов | `make check` |
| Запуск Go бэкенда (:8080) | `make backend-run` |
| Сборка Go бэкенда | `make backend-build` |
| Dev-сервер фронтенда (:5173) | `make frontend-dev` |
| Сборка фронтенда | `make frontend-build` |
| Установка ML-зависимостей | `make ml-sync` |
| Запуск ML-сервиса (:8000) | `make ml-run` |
| Запуск ML-тестов | `make ml-test` |
| Запуск всех контейнеров в Docker | `make docker-up` |
