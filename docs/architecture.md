## 2. Ключевые компоненты

### 2.1. Go Backend Core (Денис)
* **Технологии:** Go 1.26+, Chi Router, Gorilla WebSocket.
* **Назначение:**
  * Обработка телеметрии с ультра-низким latency (< 5 мс).
  * **Data Feeder:** воспроизводит исторические логи в псевдо-реальном времени с регулируемой скоростью (x1, x2, x5).
  * **Decision Engine:** расчет корректирующих воздействий:
    $$T_{hold} = \max\left(0, \frac{H_{target} - H_{current}}{2}\right)$$
  * Синхронизация состояний всех активных бортов и рассылка дельт на фронтенд.

### 2.2. ML & XAI Engine (Миша)
* **Технологии:** Python 3.11+, CatBoost, LightGBM, SHAP, FastAPI, ONNX Runtime.
* **Назначение:**
  * Прогнозирование времени прохождения перегонов с учетом истории и внешних условий.
  * Классификация вероятности пачкования ($P(\text{bunching}) \in [0, 1]$).
  * Извлечение локальных SHAP-значений для каждого сгенерированного алерта (топ-3 фактора влияния).

### 2.3. Data Engineering & Preprocessing (Артём)
* **Технологии:** Pandas, GeoPandas, Shapely, PyArrow.
* **Назначение:**
  * Проекция GPS-точек на полилинии маршрутов (Map-Matching).
  * Расчет ключевой метрики интервала:
    $$Headway_i(t) = t_{arrival}(i) - t_{arrival}(i-1)$$
  * Подготовка скользящих агрегатов (средняя скорость по сегменту за 15/30/60 мин).

### 2.4. Ситуационный дашборд (Кирилл)
* **Технологии:** React, Vite, Mapbox GL JS / Leaflet, Tailwind CSS.
* **Назначение:**
  * Полноэкранный Dark Mode интерфейс для оператора Ситуационного центра.
  * Визуализация динамических интервалов и связок между автобусами.
  * Парящие карточки с обратным отсчетом времени до сбоя.
  * Интерактивный график динамики рейса:
    * Синяя линия: нормативный график;
    * Красная пунктирная линия: траектория без вмешательства (пачкование);
    * Зеленая сплошная линия: траектория при подтверждении рекомендации ИИ.

## 3. End-to-End сценарий работы системы

1. **Генерация события:** Борт №1042 на маршруте «м3» попадает в затор на ул. Бауманская.
2. **Анализ стрима:** Go Feeder передает обновленное состояние в ML-сервис.
3. **Обнаружение риска:** Модель прогнозирует отставание на 12 минут и схлопывание интервала со следующим бортом №1043 через 22 минуты ($P=89\%$).
4. **Формирование рекомендации:** Decision Engine формирует рекомендацию: *«Придержать борт №1043 на 150 секунд на остановке м. Бауманская»*.
5. **Отображение в UI:** На левой панели оператора появляется алерт `ЧЕРЕЗ 22 МИН | м3 | РИСК ПАЧКОВАНИЯ (89%)`.
6. **Действие оператора:** Диспетчер кликает по алерту, оценивает SHAP-факторы и нажимает кнопку `[✓ Применить рекомендацию]`.
7. **Результат:** Команда фиксируется, прогнозная траектория на графике выравнивается в зеленую зону, сбой предотвращен заблаговременно.
