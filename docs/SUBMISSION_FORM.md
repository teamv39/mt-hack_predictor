### Поле 2. Ссылка на рабочую систему из 3 модулей в Docker
* **Ссылка на репозиторий:** `https://github.com/teamv39/mt-hack_predictor`
* **Команда запуска одной строкой:**
  ```bash
  git clone -b dev https://github.com/teamv39/mt-hack_predictor.git && cd mt-hack_predictor && docker compose up --build
  ```
* **Архитектура 3 изолированных микросервисов:**
  1. **ML Inference Service (`ml/`):** Python 3.12, FastAPI, CatBoost, PyTorch BiGRU, TreeSHAP. Порт `:8000`.
  2. **High-Performance Backend (`backend/`):** Golang 1.24, Chi, WebSocket Hub, TCP-сервер приема протокола NDTP (:9201), In-Memory Schedule Matcher, Headway Engine. Порт `:8080`.
  3. **Dispatcher BI Dashboard (`frontend/`):** React 19, TypeScript, Vite, Tailwind CSS v4, MapLibre GL, Recharts. Порт `:80` (и `:5173`).
  4. **NDTP Telemetry Emulator (`ndtp-emu`):** Порт `:18080` (включен в compose).

### Поле 3. Ссылка на инструкцию для жюри
* **Прямая ссылка на инструкцию:** `https://github.com/teamv39/mt-hack_predictor/blob/dev/README.md#-%D0%B1%D1%8B%D1%81%D1%82%D1%80%D1%8B%D0%B9-%D0%B7%D0%B0%D0%BF%D1%83%D1%81%D0%BA`
* **Краткий сценарий проверки жюри (Checklist за 3 минуты):**
  1. **Запуск:** Выполнить `docker compose up --build`. Все контейнеры поднимаются автоматически за ~30 секунд.
  2. **Открыть дашборд:** Перейти в браузере на `http://localhost:80` (или `http://localhost:5173`).
  3. **Проверка горизонта 10–15 минут и предиктов (Критерии 2 и 4):**
     * В левой панели **«Радар алертов»** отображаются активные инциденты пачкования (*Bus Bunching*) с горизонтом упреждения 10–15 мин.
     * Кликнуть на карточку алерта: карта выполняет плавный `flyTo` к проблемному участку перегона.
     * В правой панели **«Инспектор»** открывается сравнительный график Recharts (*План расписания*, *Прогноз без мер*, *Траектория с рекомендацией ИИ*).
     * Отображается факторный анализ **TreeSHAP** (вклад затора, отклонения от графика и простоя на остановке).
  4. **Проверка действия диспетчера (Actionable DSS — Holding):**
     * В карточке инспектора нажать зеленую кнопку **«[OK] Применить Holding (задержка 90 сек)»**.
     * Появляется Toast-уведомление, статус борта меняется на «Регулируется», интервал стабилизируется.
  5. **Проверка кабины водителя:**
     * В верхнем меню переключиться на вкладку **«Терминал борта №1043»** (`http://localhost:5173` $\to$ вкладка).
     * Открывается планшет водителя «Гранит-Навигатор v4.2» с тикающим таймером регулировочной стоянки, звуковым сигналом и кнопкой квитирования в перчатках.
  6. **Проверка интервалограммы Марея:**
     * Переключиться на вкладку **«График Марея (м3)»** — пространственно-временная траектория движения флота (Space-Time String Diagram).
  7. **Подача живого потока NDTP (Критерий 3):**
     * Go-бэкенд непрерывно слушает бинарный TCP-сокет на порту `:9201`.
     * В шапке нажать кнопку старта симуляции или отправить пакет через встроенный эмулятор.
  8. **Проверка Swagger API:**
     * Открыть `http://localhost:8080/swagger` — Swagger UI Go-бэкенда.
     * Нажать `Try it out` на `GET /api/v1/status` $\to$ возвращается `200 OK` с полной статистикой.

### Поле 5. Сведения о производительности и дополнительные возможности

#### Сведения о производительности (Критерий 5: 4/4 баллов)
Подтверждено протоколами замеров в [`docs/ml_performance.md`](https://github.com/teamv39/mt-hack_predictor/blob/dev/docs/ml_performance.md) и [`docs/backend_and_telemetry_guide.md`](https://github.com/teamv39/mt-hack_predictor/blob/dev/docs/backend_and_telemetry_guide.md):
1. **Сверхнизкая задержка ML-инференса:**
   * Инференс CatBoost: **1.31 мс** на борт.
   * Полный маршрут м3 ($N=25$ ТС): **1.74 мс** (14 395 ТС/с).
   * Сектор ($N=500$ ТС): **6.46 мс** (77 403 ТС/с).
   * Сетевой HTTP эндпоинт `/predict`: **p50 = 1.90 мс** (515 RPS).
2. **Пропускная способность и флот Москвы:**
   * Весь автобусный парк Москвы (~8 000 ТС, поток 1 600 точек/сек) обсчитывается всего за **4.2% одного ядра CPU** (запас по производительности **23.7×**).
3. **Отказоустойчивость и Graceful Degradation:**
   * При отключении или задержке ML-сервиса Go-бэкенд мгновенно переключается на встроенный эвристический предиктор за **11.1 микросекунды** (90 000+ оп/с) без потери WebSocket-сессий и без сбоев интерфейса.
4. **Холодный старт и легковесность:**
   * Холодный старт контейнеров: **0.33 с**.
   * RAM (RSS) ML-сервиса: **155 МБ**.
   * Go Backend бинарник: **< 20 МБ** (образ `scratch` / Alpine).
   * Frontend: бандл оптимизирован чанками Rolldown, основной JS всего **165 КБ**.
5. **Сетевой стек NDTP:**
   * Парсер бинарных пакетов NDTP (NPL 15 байт + NPH 10 байт + G6CellNav00 26 байт) декодирует **1 400 000+ пакетов/сек** на ядро с 0 аллокаций памяти (`0 B/op, 0 allocs/op`).

#### Дополнительные возможности (Киллер-фичи)
1. **Пространственно-временная диаграмма Марея (Marey Diagram):** Европейский диспетчерский стандарт визуализации ниток графика движения на маршруте м3 (сближение ниток при сбое и восстановление параллельности после Holding).
2. **Интерактивный бортовой терминал водителя («Гранит-Навигатор v4.2»):** Высококонтрастный планшет кабины с LED-таймером регулировочной стоянки, звуковым сигналом превышения интервала и кнопкой квитирования в перчатках.
3. **Ситуационная матрица тактических решений (What-If Engine):** 4 сценария СППР на выбор диспетчера с расчетом эффекта:
   * *Сценарий 1: Holding (удержание лидера)* — эффект 96%;
   * *Сценарий 2: Skip-Stop (пропуск остановок)* — эффект 74%;
   * *Сценарий 3: Short-Turning (оперативный разворот)* — эффект 68%;
   * *Сценарий 4: Depot Reserve (ввод резерва из парка)* — эффект 82%.
4. **Экономический калькулятор и формула Велдинга:** Расчет среднего времени ожидания пассажиров $E[W] = \frac{\bar{H}}{2}(1 + \frac{\text{Var}(H)}{\bar{H}^2})$, сэкономленных пассажиро-часов и рублей по ставке Минтранса РФ (450 ₽/пасс-ч).
5. **Интерактивный таймлайн моделирования:** Переключение срезов времени (`Сейчас`, `+15 мин`, `+30 мин`, `+45 мин`) с интерполяцией движения ТС и наглядной демонстрацией предотвращения аварийного схлопывания интервала.
6. **Автономные векторные тайлы (MapLibre):** Векторная подложка карты Москвы со стилями Light/Dark без зависимости от внешних коммерческих API-ключей.
