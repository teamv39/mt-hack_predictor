# Техническое задание: Генерация и развертывание автономного картографического сервиса Москвы для трекинга транспорта

## 1. Цель задачи

Реализовать полностью автономный (self-hosted) сервис раздачи легковесной векторной карты Москвы без сторонних платных API. Сгенерировать кастомный файл векторных тайлов, исключающий 3D/2D-контуры зданий, с акцентом на транспортную инфраструктуру (дорожный граф, метро, МЦК/МЦД, трамвайные линии, ж/д и остановки) для последующего отображения движущихся транспортных средств в реальном времени.

---

## 2. Архитектура и стек технологий

* **Источник геоданных:** Сырой дамп OpenStreetMap (`.osm.pbf`) по региону Москвы (BBBike / Geofabrik).
* **Инструмент сборки (ETL):** `Planetiler` (запуск в Docker, сборка тайлов в памяти без развертывания СУБД).
* **Формат данных:** `MBTiles` (схема OpenMapTiles, векторные тайлы Mapbox Vector Tile / Protobuf).
* **Тайловый сервер:** `TileServer GL` (Docker).
* **Фронтенд-движок:** `MapLibre GL JS` (рендеринг на WebGL).

## 3. Детальный чеклист выполнения

### Этап 1. Подготовка окружения и исходных данных

* [ ] Создать структуру каталогов проекта:
```text
map-service/
├── data/
│   ├── fonts/          # SDF-шрифты (PBF)
│   ├── sprites/        # Иконки и спрайты
│   └── moscow.osm.pbf  # Сырой экстракт
├── styles/
│   └── transport.json  # Векторный стиль без зданий
├── config.json         # Конфиг TileServer GL
└── docker-compose.yml

```


* [ ] Скачать полигональный срез Москвы в формате `.osm.pbf`:
* Использовать выгрузку Москвы с сервиса BBBike (городской срез) либо центральный округ Geofabrik, предварительно обрезав по bounding box Москвы: `[36.8, 55.1, 38.2, 56.1]`.
* Сохранить файл как `./data/moscow.osm.pbf`.



---

### Этап 2. Сборка кастомных векторных тайлов через Planetiler

* [ ] Собрать целевой файл `moscow_transport.mbtiles` с ограничением зума `z0–z14` и принудительным исключением слоя строений:
```bash
docker run --rm \
  -e JAVA_TOOL_OPTIONS="-Xmx4g" \
  -v $(pwd)/data:/data \
  ghcr.io/onthegomap/planetiler:latest \
  --osm-path=/data/moscow.osm.pbf \
  --output=/data/moscow_transport.mbtiles \
  --maxzoom=14 \
  --exclude-layers=building

```


* [ ] Проверить размер и структуру получившегося файла:
* Итоговый размер `.mbtiles` должен укладываться в диапазон **30–80 МБ**.
* Убедиться, что сохранены слои: `transportation`, `transportation_name`, `water`, `waterway`, `boundary`.



---

### Этап 3. Подготовка стилей, шрифтов и спрайтов

* [ ] Скачать набор глифов шрифтов (например, `Noto Sans Regular/Bold`) в формате `.pbf` в директорию `./data/fonts/` для отображения названий улиц и станций.
* [ ] Подготовить базовый `styles/transport.json` (MapLibre Style Spec):
* Фоновые полигоны (земля, парки) окрасить в нейтральный светло-серый тон (`#f0f2f5`).
* Водные объекты (`water`) оставить ненавязчиво голубыми (`#cad2d3`).
* Дорожный граф (`transportation`): разделить по типам (магистрали, городские улицы) с легким контрастом.
* Линии рельсового транспорта:
* `class = 'subway'` — яркие контрастные линии (ширина 2–3px на z11+).
* `class = 'tram'` — отдельный акцентный цвет.
* `class = 'rail'` — классическая штриховка или темно-серый цвет.


* Убедиться в полном отсутствии правил рендеринга для слоя `building`.



---

### Этап 4. Конфигурация и запуск TileServer GL

* [ ] Подготовить `config.json` для связки сгенерированных тайлов и стиля:
```json
{
  "options": {
    "paths": {
      "root": "/data",
      "fonts": "fonts",
      "sprites": "sprites",
      "styles": "styles",
      "mbtiles": ""
    }
  },
  "data": {
    "moscow-transport": {
      "mbtiles": "moscow_transport.mbtiles"
    }
  },
  "styles": {
    "transport": {
      "style": "styles/transport.json",
      "tilejson": {
        "type": "vector",
        "bounds": [36.8, 55.1, 38.2, 56.1]
      }
    }
  }
}

```


* [ ] Описать сервис в `docker-compose.yml`:
```yaml
version: '3.8'

services:
  tileserver:
    image: maptiler/tileserver-gl:latest
    container_name: moscow-map-tileserver
    restart: unless-stopped
    ports:
      - "8080:80"
    volumes:
      - ./data:/data
      - ./styles:/data/styles
      - ./config.json:/data/config.json
    command: ["--config", "/data/config.json"]
    deploy:
      resources:
        limits:
          memory: 2G

```


* [ ] Запустить контейнер командой `docker compose up -d` и верифицировать доступность сервиса.

## 4. Критерии приемки (Definition of Done)

1. **Генерация данных:**
* Процесс Planetiler завершается с кодом `0`.
* Файл `moscow_transport.mbtiles` существует, не поврежден, его объем не превышает 100 МБ.
* В схеме отсутствуют объекты полигонов зданий.


2. **Работа серверной части:**
* Сервис `tileserver` стартует без ошибок в Docker и отдает `HTTP 200` на запросы:
* `GET http://localhost:8080/styles/transport/style.json`
* `GET http://localhost:8080/data/moscow-transport/11/1238/639.pbf` (любой тестовый тайл Москвы).


* Время ответа сервера (TTFB) на локальные запросы тайлов не превышает **40 мс**.


3. **Отображение на клиенте:**
* Карта зумится от z0 до z18 без разрывов (срабатывает оверзум для уровней выше z14).
* На карте отображаются дороги, реки, ветки метро, ж/д пути и подписи улиц/станций.
* На карте полностью отсутствуют 3D-экструзии и контуры домов.
* Тестовый динамический слой с маркером транспорта плавно рендерится поверх подложки без задержек основного цикла рендера карты.
